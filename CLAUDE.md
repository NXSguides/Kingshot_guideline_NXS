# Working on the NXS Guidelines site

- **Little Sparrow and the AI are always updated together.** Any new or changed feature (site or officer page) gets
  its Little Sparrow step (`js/sparrow.js`, officer pages: `OTOURS` + texts in en / zh / pt / ar / ko; main site: 12 languages)
  AND its AI text (`worker/worker.js` `OFFICER_HELP` for officer pages, `scripts/build-ai-context.js` SITE FEATURES for the site),
  plus one row in `FEATURES` in `scripts/check-help.js`. That script runs in CI and in the smoke test and fails if one side is missing.
- **Officer permissions apply to the AI too.** Every officer-handbook part belongs to a tab (`@tab` block or `[tab] ` line in
  `OFFICER_HELP`); officer data parts are mapped in `DATA_TABS`. The Worker only gives the AI the parts of tabs the asking officer
  may open (Discord login + the 👥 table). A new tab or new officer data → tag it, never leave it untagged.
- Guide text: edit `data/content.js`, then `node scripts/split-content.js` and `node scripts/build-ai-context.js`.
- `node scripts/check-lang.js` (in CI and the smoke test) fails when a guide text is not in its own language, a title was copied from another language, or an English officer text has Chinese in it. `--all` also lists softer notes (missing languages, different block counts).
- Public research pages (🔬 Research Reports in the top row; `research.html?r=…`, `research-viking.html`, `css/research.css`): `research.html` is generated from the officer page — after changing officer styles or a public report's section markup run `node scripts/build-research.js`. It runs the officer report code and hides what is not for members (🟡 not-known cards and lines, 🔢 how-we-worked-it-out, videos, name notes). The 7 languages the officer page lacks are in `data/research-i18n.js` (sources `scripts/research-i18n/`): when a public report's English text changes, that sentence needs retranslating. Nothing that names the private stats source, a member, or a data count goes on these pages.
- Every change: bump `CACHE` in `sw.js`, run `node scripts/smoke.mjs` (and `bash scripts/worker-test.sh` if the Worker changed).
- Never put a `// comment` in the middle of a line that has more code after it: everything behind `//` stops running (found 2026-11-18: three such lines, one had been dropping event reminder times since 2026-11-02). Comment at the end of the line or on its own line; `scripts/check-help.js` fails on it.
- Never commit plaintext officer or member data; never put secrets (VAPID private key, DISCORD_CLIENT_SECRET, OFFICER_PASSWORD) anywhere but Cloudflare / GitHub secrets.
- **Write for the page's reader.** No explaining what readers already know, and no common-sense points every player knows (e.g. "strong rallies fill fast", "fill the rally", what a fill-in rally is) — only what our data adds. Research reports are read by members / officers so they can understand the gist and explain it to others: lead with what we observed and then suggestions, in plain short points — findings and advice, never orders (no "do this"). How it was worked out (formulas, data counts, sources, fits) goes in one folded section at the bottom or not at all. Never put Sherry's to-dos, capture requests, correction history or internal notes on a page — those go in the Project docs.
- **Bear Hunt: "leader" = the official A / B list only** (Project doc `claude/bear-findings.md` G0). Everyone else who opens a rally is a **non-leader (非隊長 — always this word, never "fill-in" / 補位)**; they open in the last minutes to collect returning troops: show them apart, never count or compare them as leaders, never draw conclusions from them.
- **No last-login / online / "active in 24 h" anywhere** (Sherry 2026-11-18: "我本來就不需要最後上線"; the game also stopped sending activity data). Do not collect, store or show it.
- **Data tables show only what the source gives.** Numbers we work out ourselves (e.g. the Swordland Squad Power estimated from the Migrant Score, Transfer Pass estimates) appear only where they are the point — the Swordland plan — never as extra columns in the roster, Scout, Transfer or other fetched-data tables.
- **Three names (since 2026-11-21): NXS = main alliance, nXs = second alliance, nxs = our farm.** They are different alliances, never a rename. On the officer page the second alliance (internal code `f`) is nXs; the old nxs only survives as the attached layer on 🚩 Territory (`PLAN.farm.sub`, shown, holds its tiles, add / remove by hand, never planned; the plan parts of the old set — `fl`, `bt`, `btp`, `c` — were copied to nXs once, `g: 2 → 3`, and `move-plan-n2` began as a copy of `move-plan-nxs`). Stored on the Worker: nXs = `w: "x"` / `rk:btx`; the old nxs's `w: "f"` / `rk:btf` items are kept but not listed. Files: nXs = `data/n2-roster`, `data/watch-n2`, `data/move-plan-n2`; nxs's old `academy` / `watch-nxs` / `move-plan-nxs` files stay untouched.
- **🗂️ My workspace (`js/officer/ws.js`, Worker `/ws`, since 2026-11-22) is private.** One page per admin, stored on the Worker under their own Discord id (`ws:<id>`). Only that person reads and writes it; Sparrow (`ADMIN_IDS[0]`) may also read another person's page, never write it. Its content never goes into an AI data part, the AI context, Little Sparrow, a repo file or a log; no names in the code (the "for" list is part of each person's data).
